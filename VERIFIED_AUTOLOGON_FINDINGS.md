# Verified Autologon Findings - Real-World Testing

**Date:** February 25, 2026  
**Test Environment:** Production Windows system with assigned access configuration  
**Testing Method:** Direct verification on configured system

---

## Executive Summary

Real-world testing has confirmed that previous documentation about Assigned Access autologon was **partially incorrect**. The key finding is that **password policies do NOT break Assigned Access autologon**.

### Critical Corrections

**❌ INCORRECT (Previous Documentation):**
- KioskUser0 account has no password / blank password
- Password policies (complexity, minimum length, age) break Assigned Access autologon
- Need to disable password policies

**✅ CORRECT (Verified):**
- KioskUser0 account DOES have a password
- Password IS stored in LSA secrets (encrypted)
- Password is automatically generated by Windows (random, highly complex)
- Password is automatically managed by Windows
- Password policies do NOT break Assigned Access autologon
- No password policy modifications needed

---

## What Actually Breaks Assigned Access Autologon (VERIFIED)

### 1. Interactive Logon Legal Notices ❌ BREAKS AUTOLOGON

**Settings:**
- `LegalNoticeCaption` - Interactive logon: Message title for users attempting to log on
- `LegalNoticeText` - Interactive logon: Message text for users attempting to log on

**Registry Location:**
```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LegalNoticeCaption
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\LegalNoticeText
```

**Why it breaks autologon:**
- Requires interactive user acknowledgment (clicking OK)
- Microsoft documentation explicitly states this breaks autologon
- Applies to both domain-joined and standalone systems

**Mitigation:**
- Set to empty/not configured for kiosk devices
- Display legal notice within kiosk application instead
- Create GPO exemption for kiosk OU

### 2. Machine Inactivity Timeout ❌ INTERRUPTS KIOSK

**Setting:**
- `InactivityTimeoutSecs` - Interactive logon: Machine inactivity limit

**Registry Location:**
```
HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System\InactivityTimeoutSecs
```

**Why it breaks kiosk:**
- Forces logoff/lock after inactivity period
- Requires re-authentication
- Disrupts kiosk user experience

**Mitigation:**
- Set to 0 (disabled) for kiosk devices
- Set to very high value if policy required
- Create GPO exemption for kiosk OU

## What Does NOT Break Assigned Access Autologon (VERIFIED)

### Password Policies ✅ ALL COMPATIBLE

All password policies have been verified to work correctly with Assigned Access autologon:

| Policy | STIG Requirement | Impact on Autologon | Status |
|--------|------------------|---------------------|--------|
| **Password complexity** | V-253304: Enabled | ✅ NO IMPACT | Works fine |
| **Minimum password length** | V-253303: ≥14 characters | ✅ NO IMPACT | Works fine |
| **Maximum password age** | V-253301: ≤60 days | ✅ NO IMPACT | Works fine |
| **Minimum password age** | Varies | ✅ NO IMPACT | Works fine |
| **Password history** | Varies | ✅ NO IMPACT | Works fine |
| **Account lockout threshold** | Varies | ✅ NO IMPACT | Works fine |

**Why they work:**
- Windows automatically manages KioskUser0 password
- Password is stored in encrypted LSA secrets
- Password meets all policy requirements automatically
- No manual configuration needed

## Recommended Script Changes

### Set-WindowsAppFromEdgeKioskSettings.ps1

**Current behavior (Lines 560-620):**
```powershell
# Configure password policies for S4U autologon compatibility
# Applies S4U-PasswordPolicies.inf
```

**Recommended change:**
```powershell
# NOTE: Password policies do NOT break Assigned Access autologon (verified 2026-02-25)
# Assigned Access autologon stores auto-generated password in LSA secrets and Windows manages it automatically
# All password STIG requirements (V-253304, V-253303, V-253301) are compatible
# The following section has been disabled as password policy modifications are no longer needed:

<#
# DISABLED: Password policy modifications (not required)
Write-Log -EventLog $EventLog -EventSource $EventSource -EntryType Information -EventId 87 -Message "Password policy configuration is not required for Assigned Access autologon. Storage in LSA secrets allows all password policies to be enforced."
#>

# Check for settings that actually break autologon (verified)
$LegalNoticeText = Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "LegalNoticeText" -ErrorAction SilentlyContinue
$LegalNoticeCaption = Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "LegalNoticeCaption" -ErrorAction SilentlyContinue
$InactivityTimeout = Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" -Name "InactivityTimeoutSecs" -ErrorAction SilentlyContinue

If (($LegalNoticeText.LegalNoticeText -and $LegalNoticeText.LegalNoticeText.Length -gt 0) -or ($LegalNoticeCaption.LegalNoticeCaption -and $LegalNoticeCaption.LegalNoticeCaption.Length -gt 0)) {
    Write-Log -EventLog $EventLog -EventSource $EventSource -EntryType Warning -EventId 88 -Message "WARNING: Legal notice (LegalNoticeText/LegalNoticeCaption) is configured. This WILL BREAK Assigned Access autologon. Create a GPO exemption for kiosk devices or set these values to empty."
}

If ($InactivityTimeout.InactivityTimeoutSecs -and $InactivityTimeout.InactivityTimeoutSecs -gt 0) {
    Write-Log -EventLog $EventLog -EventSource $EventSource -EntryType Warning -EventId 89 -Message "WARNING: Machine inactivity timeout is set to $($InactivityTimeout.InactivityTimeoutSecs) seconds. This can interrupt kiosk sessions. Set to 0 for kiosk devices."
}

# Domain membership check for GPO conflicts (legal notices only)
$ComputerSystem = Get-WmiObject -Class Win32_ComputerSystem
If ($ComputerSystem.PartOfDomain) {
    Write-Log -EventLog $EventLog -EventSource $EventSource -EntryType Warning -EventId 91 -Message "WARNING: This system is domain-joined. Domain Group Policies for legal notices (LegalNoticeText/LegalNoticeCaption) or machine inactivity timeout may prevent Assigned Access autologon. Password policies are fully compatible. Work with your domain administrator to create GPO exemptions for kiosk devices."
}
```

## Summary: What Changed

### Previous Understanding (INCORRECT)
- Assigned Access autologon = no password stored anywhere
- Password policies break autologon
- Must disable password complexity and minimum length

### Verified Reality (CORRECT)
- Assigned Access autologon = automatically generated random, highly complex password stored in **LSA secrets** (encrypted)
- Password is automatically managed by Windows
- Password policies **do not** break autologon
- All STIG password requirements are compatible
- No password policy modifications needed
- Only legal notices and inactivity timeout break autologon

### Benefit for STIG Compliance
- ✅ Stronger security posture (password policies can be enforced)
- ✅ Simpler deployment (fewer GPO exemptions needed)
- ✅ Better documentation (accurate understanding of mechanisms)
- ✅ Reduced attack surface (password complexity enforced)
